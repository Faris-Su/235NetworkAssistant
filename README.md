## 1. 它能做什么

一句话：**把交换机的 CLI 输出变成能看的表格，并且把改配置这件事做得"先预览、后执行"**。

| 页面 | 用来干什么 |
| --- | --- |
| 🏠 概览 | 当前设备状态、常用入口、**Ping / Tracert 网络工具**、最近操作记录、SNMP 简报卡片 |
| 🔌 连接 | 交换机地址簿 + Console / Telnet 参数 + 连接 / 断开 / **连通性自检** |
| 💻 CLI | 真终端：直接打字给设备，或按行发送（两种模式可切换） |
| 🔌 端口 | 端口状态表 + 批量配置（Access / Trunk / 速率 / 双工） |
| 🟢 VLAN | VLAN 列表 + 创建 / **改名** / 删除 + 端口批量划入 Access VLAN |
| 🟠 Trunk | Trunk 端口表 + 设为 Trunk / Allowed VLAN 增删 / Native VLAN |
| 🟣 LLDP | 邻居列表 + 详情 + 一键 Telnet 到邻居 |
| 🔎 MAC/IP | **定位一台设备接在哪个口**：MAC ↔ IP ↔ VLAN ↔ 端口，并对上资源库规划信息 |
| 📡 SNMP | **独立** SNMP v2c 查询（不需要连 Console/Telnet）：系统 / CPU·内存 / 温度 / 风扇 / 电源 / 接口 / VLAN / MAC / IP + **SNMP 信息库**（按设备保存的查询结果） |
| 📊 设备 | Show Center：8 类 show 命令的结构化结果 + 原始输出 |
| 💾 备份 | 备份 running-config 到本地，带历史列表 |
| 💾 保存到设备 | 顶栏常驻 **[保存配置]**：`write` 写入启动配置，需**按住 1.2 秒**确认（见 3.13） |
| 📚 资源库 | 离线查询 VLAN / IP / 楼栋 / 房间，可编辑、可导出 CSV |
| ⚙ 设置 | Excel 导入、终端与外观设置、备份目录、日志等级、SNMP 配置 |

**核心特点**

- **完全离线**：资源库是本地 JSON，不连任何在线服务；只有你点[刷新]才会与设备通信
- **绝不自动改设备**：所有配置修改都先弹 Command Preview，你确认后才发送；**永远不会自动执行 `write`**
  （保存配置是**显式动作**：顶栏 [保存配置] → 弹窗里**按住 1.2 秒**才写入，见 3.13）
- **原始输出永远保留**：解析失败也只提示、不猜测；任何页面都能展开看设备原文并复制

## 2. 快速开始

### 第 1 步：连上交换机

打开【连接】页，你会看到两个**折叠面板**（默认都收起，展开一个会自动收起另一个）：

```
▶ Console / Serial（配置线连接）      ← 用 USB 转配置线插交换机 Console 口
▶ Telnet                              ← 用网线连，需要交换机管理 IP
```

**走 Console（配置线）**：展开第一个面板 → 点 **[刷新串口]** → 在下拉里选实际存在的 COM 口 → 点 **[连接 Console]**

**走 Telnet（网线）**：先给电脑网口配一个和交换机管理 IP **同网段的静态 IP**（例：交换机 `192.0.2.49`，电脑配 `192.0.2.50 / 255.255.255.0`）→ 展开 Telnet 面板 → 填 Host → 点 **[连接 Telnet]**

> 上方**交换机地址簿**可以在资源库里搜交换机（按名称 / IP / 楼栋），选中后点 **[填入 Telnet 参数]** 或直接 **[连接 Telnet]**。

连接前还有一项**登录权限模式**（在连接面板下方，两个面板共用）：

| 选项 | 连接后会发生什么 | 什么时候选 |
| --- | --- | --- |
| **管理模式**（默认） | 连接成功后自动执行 `enable`；如果设备要密码就自动输入下面的 Enable 密码 | 你要改配置（VLAN / Trunk / 端口），推荐 |
| 普通模式 | 保持设备当前权限，不执行任何额外命令 | 只想看看，或这台设备不方便用 enable |

**Enable 密码**输入框默认留空，请按设备实际配置填写。
它只存在内存里：**不写入设置文件、不写日志、不弹框显示**。

### 第 2 步：确认连接状态

连接后顶部状态栏和页面标题会显示状态。**状态含义很重要**：

| 显示 | 含义 | 能用吗 |
| --- | --- | --- |
| 连接中 | 正在建立 TCP / 打开串口 | 否 |
| 已连接（正在登录） | 底层已连上，正在自动登录 | 可以，随时切 CLI 手动操作 |
| **已连接（CLI 未确认）** | 底层已连上，但没等到命令提示符 | **可以**，按钮下方会给出原因 |
| **已连接** | 已验证 CLI 可用（看到提示符） | 可以 |
| **连接失败** | **只有**底层连不上（TCP 拒绝/超时、串口打不开）才是这个 | 否 |

> 记住这条：**只要不是"连接失败"，就说明链路是通的**。这时去 CLI 页手输命令往往就能继续干活。

状态栏同时会显示**当前权限**（`#` 能改配置，`>` 只能看）：

| 显示 | 含义 |
| --- | --- |
| 🟢 特权模式 # | 已进入特权模式，改配置的操作可以直接执行 |
| 🟡 普通模式 > | 只能查看；需要改配置时点[提升权限]即可 |

> **进不了特权模式不是连接失败**。Enable 密码不对时软件会明确说"设备已连接，但是进入管理模式失败：Enable 密码不正确"，
> 连接保持可用，CLI 照常能敲命令，填对密码再点[提升权限]就行。

### 第 3 步：开始用

1. 先去 **CLI** 页敲一条 `show version` —— 能看到回显和输出，说明整条链路正常
2. 再按需要去 VLAN / 端口 / Trunk / LLDP / MAC-IP 等页面点 **[刷新]**
3. 要改配置：填参数 → **[生成命令并预览]** → 在弹窗里核对命令 → 点[执行]

## 3. 使用指南

### 3.0 概览页的网络工具（Ping / Tracert）

【概览】页左下角有 **网络工具**：

```
目标 [192.0.2.49]   [Ping]  [Tracert]  [停止]
────────────────────────────────────────────
（结果区，显示每一包延迟 / 每一跳地址与延迟）
```

- **Ping**：连续 4 次 ICMP（超时 1.5 秒），逐包显示延迟，最后给出发送/接收/丢包与最小·最大·平均
- **Tracert**：逐跳跟踪到目标（最多 15 跳，每跳 1 秒）；交换机/防火墙常不回 ICMP 超时包，该跳显示 `*` 属正常
- 目标默认填当前设备 IP（没有连接时用 SNMP 页上次查过的 IP），也可以填任意域名；**不依赖任何连接**
- 全程异步，随时可点 **[停止]**；结果也会记进"最近操作记录"

### 3.0.1 概览页的「管理 IP」[获取] 按钮

【概览】页 → 当前设备 → **管理 IP** 那一格后面有个 **[获取]**：

- 点一下，软件发一次只读命令 `show ip interface brief`，从设备的三层接口里挑出它的**真实管理 IP** 填进这一格。
  **不用**再专门跑到【设备】页去点「三层接口」。
- 有值之后按钮变成 **[重取]**，点了会覆盖成最新读到的地址。
- **只在点按钮时才发命令**：没连接、或登录还没走完（CLI 未就绪）时按钮是灰的，悬停会说明原因 ——
  登录没走完就发命令，会被设备当成用户名/密码吃掉，把会话搅乱。
- 配置线（Console）连上后同样能用：那一格没读过时显示「—（未获取）」，旁边就是同一个按钮。
- **隧道 / 端口映射场景**：那一格先显示的是拨号地址（例如 `127.0.0.1`），
  点[获取]之后才会换成交换机自己的管理 IP —— 那一行小字会写清当前显示的是哪种。
- 断开连接会清空读到的值（换设备不串台）；重新连上再点一次即可。

### 3.1 用 CLI（两种输入模式）

【CLI】页工具条上有 **☑终端模式** 开关，两种模式随时切换（会记住）：

| | **终端模式**（默认，像 Xshell） | 行模式 |
| --- | --- | --- |
| 输入位置 | **点一下终端就能打字**，光标在终端里 | 页面下方单独的输入框 |
| 发送时机 | 字符**逐个**发给设备，设备回显就是屏幕上那一行 | 回车 / [发送] 时整行发送 |
| ↑ / ↓ | 送给设备的**设备侧历史**（和 Xshell 一致） | 本地历史：把上一条命令填回输入框 |
| Tab | 发送 `\t` 给设备做命令补全 | 同左 |
| `?` | 直接作为字符发送（设备侧帮助） | 立即把"当前输入 + ?"发给设备 |
| Ctrl+C | 没选中文字 → 发送中断字符 `0x03`；**选中文字 → 复制** | 同左 |
| Ctrl+V | 剪贴板内容原样发给设备 | 粘贴进输入框，回车再发 |

> **空格与退格**：终端模式下空格、退格都是直接发给设备的（退格发 `0x08`，设备删除后回显的擦除序列
> 会在屏幕上真正生效，字符会消失）。所以 `conf t` 这类带空格的命令可以直接打，不用靠 Tab 补全。

其他常用按钮：

- **本地回显**：某些老设备不回显你输入的内容，勾上它就能看到自己打的字
- **自动滚动**：新输出自动滚到底部
- **清空**：清屏幕显示，**不影响**已记录的原始输出
- **保存输出**：导出本会话的**完整**原始输出（不受屏幕缓冲上限影响）
- **专注 CLI**：隐藏导航与状态栏，终端占满窗口（`Ctrl+L`，`Esc` 退出）

### 3.2 看端口

【端口】页 → **[刷新端口]**（执行 `show interface status`）。

- 表格显示：Port / Status / VLAN / Duplex / Speed / Type / LLDP 邻居
- 要配置：在 **「选」列直接点一下复选框**就能勾上端口（表头那个复选框是全选/取消全选），
  也可以手工输入 `g0/1-3,g0/5` → 选操作 → **[生成命令并预览]**
- 勾选后会实时显示"将影响 N 个端口：…"，生成命令前能先核对一遍
- **[获取 LLDP 邻居]**：把邻居设备名填到 LLDP 列，方便判断这根线对面是谁
- 页面底部可展开 **原始输出**，任何时候都能看到设备原文

### 3.3 看 / 改 VLAN

【VLAN】页 → **[刷新 VLAN]**（`show vlan`）。表格显示 VLAN ID / 名称 / 状态 / 端口数 / 端口。

三种改法（都会先出命令预览）：

| 操作 | 步骤 |
| --- | --- |
| **创建 VLAN** | 填 VLAN ID + 名称 → [预览创建命令] |
| **修改名称** | 在列表里**选中**该 VLAN → 新名称框会自动填入当前名称，改成新名字 → [预览改名命令] |
| **删除 VLAN** | 选中 → [预览删除选中 VLAN]（危险操作，会提示影响范围） |
| **端口划入 Access VLAN** | 填端口（如 `g0/1-3`）+ VLAN ID → [预览划入命令] |

> 改名用的是 `vlan X` → `name Y` 的配置上下文，**不会**删除再重建（那样会丢端口和业务）。

### 3.4 看 / 改 Trunk

【Trunk】页 → **[刷新 Trunk]**。表格显示 Port / Mode / Encap / Status / Native / Allowed VLANs / Active VLANs。

配置区（先填端口，或从表格选中后点[使用选中端口]）：

- **设为 Trunk**：把端口改成 trunk 模式
- **放通 VLAN（add）** / **移除 VLAN（remove）**：填 VLAN 列表，如 `200-202,210`
- **设置 Native VLAN**：**危险操作**——两端必须一致，否则会出问题

### 3.5 看 LLDP 邻居

【LLDP】页 → **[刷新 LLDP]**。**点一次就拿到完整信息**，不需要再一个端口一个端口点详情。

后台实际做了两步：

```
① show lldp neighbors                                   ← 基础邻居 + 本地端口列表
② 对每个有邻居的本地端口顺序执行：
   show lldp neighbors interface <本地端口> detail       ← 例如 g0/1、g0/2 …
③ 合并 → 表格直接显示 Detail 字段
```

表格列（只放关键字段，小屏不用横向滚动）：本地端口 / 邻居设备 / 邻居端口 / 管理 IP / Capability / Status。

- 刷新时会显示进度：**正在获取 Detail 3 / 7：g0/3**，软件不会卡死
- **顺序执行**，不会同时向设备发几十条命令；输出长会自动处理 `--More--`（发空格续页）
- 右侧详情面板：选中一条邻居 → 显示完整字段（Chassis ID / System Description / Port Description /
  Capability / Aging Time / 更新时间 …），字段缺失显示 **N/A**
- 详情面板已**全中文化 + 图形化**：
  - 顶部是**链路示意**：`[本机 · Te0/25] ── LLDP ── [邻居 · SW-Example-A]`，
    下面一行写清"谁连到谁的哪个口"
  - **设备能力**显示为徽标（网桥 / 路由器 / 无线 AP …），不再是一串 `B, R` / `Bridge, Router`
  - 字段表逐行带图标与中文标签，取值也翻译：
    `Aging-time: 1minutes 35seconds` → **信息老化时间：1 分 35 秒**；
    `Update time: 0 days, 0 hours, 5 minutes` → **邻居信息更新：5 分钟前**；
    `Chassis type: MAC address` → **机箱 ID：0200.0000.0001（MAC 地址）**
  - 邻居没有管理 IP 时写"**未获取（无法直连 Telnet）**"，而不是干巴巴的 N/A
- **[重新获取详情]**：单个端口重查（刷新时 Detail 失败的端口可以在这里重试）
- **[复制详情]**：把完整字段复制成文本，方便贴到工单 / 微信 / 文档
- **[Telnet 到邻居]**：邻居有管理 IP 时一键连过去并跳到 CLI；没有管理 IP 时按钮是灰的
- **[查看本地端口]**：跳到端口页并选中该端口

Status 列的含义：

| Status | 含义 |
| --- | --- |
| 已获取 | 该端口 Detail 已取到并合并进表格 |
| 获取失败 | 该端口 Detail 查询/解析失败，**已保留基础 LLDP 信息**（可单独重试） |
| 不支持 | 设备不支持 `... detail` 命令，已保留基础信息并停止继续查询 |
| 仅基础 | 该行只有 `show lldp neighbors` 的基础字段 |

### 3.6 定位一台设备（MAC/IP 页）

这是排查"某台电脑在哪"的主力页面。三条数据来源要分清：

| 来源 | 从哪来 | 内容 | 用途 |
| --- | --- | --- | --- |
| **ARP 表**（默认显示） | 设备实时（[刷新 ARP 表]） | IP ↔ MAC ↔ VLAN ↔ 接口 ↔ 老化时间 | **静态 IP（服务器 / 打印机 / AP）只在这里有**；租约没过期时也最快 |
| **MAC 地址表** | 设备实时（[刷新 MAC 表]） | MAC → VLAN → 端口 → 类型 | 这台设备接在**哪个口** |
| **DHCP Snooping 绑定** | 设备实时（[刷新 DHCP Snooping]） | IP ↔ MAC ↔ VLAN ↔ 端口 ↔ 租期 | 把 **IP 和 MAC 对上号** |
| **资源库规划信息** | 本地 Excel（不连设备） | 该 IP 属于哪个 VLAN / 网关 / 掩码 / 楼栋房间 | 这台机器**应该在**哪 |

> 页面默认停在 **ARP 表** 这一页（IP ↔ MAC 最常用）。ARP 表里的条目会老化，
> "这台机器刚才还在、现在查不到"通常是 ARP 过期了 —— 重新点一次 [刷新 ARP 表] 即可。

用法：

1. 点 **[刷新 ARP 表]**（默认这一页）、**[刷新 MAC 表]**、**[刷新 DHCP Snooping]**（各读一次设备数据）
2. 输入 **MAC 或 IP** → **[查询]**（这一步是**本地查询**，不再发命令，可以反复查）
3. 想进一步查规划信息 → **[在资源库中查询]**

典型输出：

```
查询 IP：192.0.2.50
DHCP 绑定：MAC 02:00:00:00:00:03｜VLAN 200｜Port GigabitEthernet 0/3
MAC 地址表：VLAN 200｜Port Gi0/3｜Type DYNAMIC
资源库规划信息：VLAN 示例｜网关 192.0.2.1｜位置 示例区域
```

**注意事项**

- MAC 表会**老化**（通常 5 分钟）：设备拔掉或空闲久了，"未找到"是正常的
- **IP 查不到 ≠ IP 不通**：静态 IP、或跨网段（不属于本交换机的 VLAN）都不会出现在 Snooping 表里
- 设备没开 DHCP Snooping 时，IP 查询只能给出资源库的规划信息（界面会提示）

### 3.7 设备信息（Show Center）

【设备】页：下拉选择命令 → **[刷新]**。可选：基本信息 / 接口状态 / VLAN / MAC 地址表 / 三层接口 / CPU / 日志 / 运行配置。

- 能可靠解析的 → 结构化表格
- CPU / 日志 / 运行配置 → 直接显示原始文本（不做猜测解析）
- **[复制结构化结果]** / **[复制原始输出]** 方便贴到工单或微信

> 本页只做"读设备"。SNMP 相关的**信息库已移到【SNMP】页底部**（见 3.10），设备页不再有 SNMP 面板。

### 3.8 备份配置

【备份】页 → **[备份 running-config]** → 生成 `设备名_YYYYMMDD_HHmmss.cfg` 存到本地备份目录。

**查询**（在【资源库】页）：

### 3.10 SNMP（独立页面，只读）

【SNMP】页是**独立模块**：**不需要** Console / Telnet / SSH 连接，只要「IP + Community + UDP 端口」。

```
目标 IP [192.0.2.49]   版本 [v2c]   Community [••••••] 👁   UDP 端口 [161]   [查询]  [信息库]
```

1. 填 **IP** 与 **Community**（默认隐藏，点 👁 显示明文）→ 点 **[查询]**
2. 已连了设备时，可点 **[使用当前设备 IP]** 一键填入（只是省事，SNMP 本身不依赖该连接）
3. 结果按分类显示在左侧：**CPU / 内存、温度、风扇、电源、接口、VLAN、MAC、IP、其他**
4. 查询过的设备会按 IP 存进**信息库**：就在**本页底部**的「SNMP 信息库」面板，
   或点顶栏 **[信息库]** 一键展开（含最后查询时间、历史快照次数）

**自动刷新**：总开关默认 **OFF**（每次启动都是 OFF）；打开后可选 5 / 10 / 15 / 20 / 30 / 60 / 120 秒
（5 秒为最小步进）。上一轮查询还没结束时，这一轮会**直接跳过**，不会叠加、不会拖死界面。

**SNMP 信息库（就在本页底部，不需要再去【设备】页）**：软件查过哪些设备，就按 **IP** 保存查询结果 +
最后查询时间 + 最近 100 次历史快照（`snmp-devices.json`）。点顶栏 **[信息库]** 或页面底部的
「SNMP 信息库」标题即可展开面板：
左上选设备 → 右边看该设备保存的字段与分类表；同一 IP 重复查询只更新它自己那一条。
**信息库里只有查询结果，没有 Community**。

其他约定：

- 单个字段取不到就显示 `N/A`，**不会**让整页失败；某张表取不到也只是那张表显示 N/A
- **表类信息统一用 WALK（GETNEXT）取**：不同型号的传感器数量/索引写法不同，
  WALK 会自动适配，不会出现"温度/风扇/电源整张表都空"的情况
- **设备名 / 接口清单用标准 MIB**：设备名取标准 `sysName`（`1.3.6.1.2.1.1.5.0`）、
  接口用标准 IF-MIB（`ifName/ifOperStatus/ifHCInOctets`…）——这样才能看到**电口 + 光口全部接口**，
  而不是只看得到锐捷私有光模块表里的 4 个万兆口
- **Community 永远不会被当成设备名**：早期误用私有分支里的团体名当设备名的错误已修正
- 锐捷私有 OID 只用于标准 MIB 没有的信息（型号 / 序列号 / CPU·内存 / 温度 / 风扇 / 电源 / VLAN / MAC / ARP），
  含义没确认的列会明确标注「推断值 / 含义未确认」，不做猜测解释（见 [docs/snmp.md](docs/snmp.md)）
- **Community 等同密码**：只存在内存里，不写设置文件、不写日志、不进设备信息库，**重启程序后要重新填**
- 概览页保留一张**简报卡片**（型号 / 版本 / 序列号 / 内存 / 运行时间）+ [打开 SNMP] / [刷新 SNMP]

### 3.12 登录权限（普通模式 / 管理模式）

一句话：**权限在连接时就确定好，不在改配置的中途弹登录窗口**。

**连接时自动提权（管理模式）**

```
连接 → 用户认证 → 看提示符
                     ├─ 已经是 Host#  → 直接可用（特权模式）
                     └─ 是 Host>     → 自动 enable → 设备要密码就发 Enable 密码
                                        ├─ 变 Host#  → 特权模式，改配置直接可用
                                        └─ 密码错     → 保持已连接，提示"提权失败"，权限停在普通模式
```

**普通模式下点改配置会怎样**

在 VLAN / Trunk / 端口页生成命令后，Command Preview 弹窗里会多出一块**「需要管理权限」**面板：

1. 填 Enable 密码 → 点 **[提升权限]**
2. 提权成功后会**自动接着执行**刚才那条命令，不需要你再点一次
3. 不想提权就点 **[继续普通模式]**，本次操作取消（连接不受影响）

**CLI 里手动 enable 也认**

在 CLI 页自己敲 `enable` 并用 `enable` 密码进入 `#` 之后，图形化页面会立刻识别到权限变化，
状态栏同步变成 🟢 特权模式 #，不需要重新连接。

**为什么"选了普通模式还是显示特权模式"**

「普通模式 / 管理模式」管的是**连接时要不要自动执行 enable**，不是给账号降权：

| 现象 | 说明 |
| --- | --- |
| 普通模式 + 显示 🟢 特权模式 # | **正常**：这个账号登录后本来就在 `#`，普通模式不会主动降权 |
| 普通模式 + 显示 🟡 普通模式 > | 正常：账号是普通级别，需要改配置时点[提升权限] |
| 管理模式 + 显示 🟡 普通模式 > | 说明自动 enable 没成功，页面会写明原因（多为 Enable 密码不对） |

连接页里 [提升权限] 按钮旁边**永远会写清它当前为什么可用/不可用**，例如"当前已经是特权模式（#），
可以直接改配置，不需要提升权限。"——按钮变灰时先把这句话读一遍。

**断开 / 重连**

断开时权限状态会复位成"未知"，重连后按当前选择的权限模式重新判定，不会沿用上一台设备的权限。

### 3.13 保存配置到设备（write）

改完配置（VLAN / Trunk / 端口 / CLI）后要**写进设备启动配置**，用这个：

```
顶栏 [💾 保存配置]  或  CLI 页工具条 [💾 保存配置]
        ↓
确认弹窗（看清是哪台设备 + 要发什么命令）
        ↓
按住按钮 1.2 秒（进度条走满；中途松手 = 取消）
        ↓
设备回显 [OK] → 弹窗显示"已保存"，并保留原始回显
```

**命令**：默认 `write`；如果设备回 `% Invalid input`（部分型号/版本不认），弹窗会提示并给
**[改用 write memory]** 按钮 —— 换写法后**仍需重新按住确认**，软件不会自己换命令重试。

**为什么是"按住 1.2 秒"**（防误触设计）：

| 闸门 | 具体行为 |
| --- | --- |
| ① 入口 | 未连接 / 普通模式（>）/ 刚保存过（5 秒冷却）时，按钮直接不可用并说明原因 |
| ② 弹窗 | 点按钮**不会写设备**，只是打开确认窗（设备名 / 管理 IP / 连接方式 / 当前权限 / 将发送的命令） |
| ③ 按住 | 鼠标按住不放满 1.2 秒才开始写入；中途松手、鼠标移开、窗口失去捕获都算取消；**回车 / 空格不会触发** |
| ④ 权限 | 普通模式先点[提升权限]；**提权成功后不会自动写入**，必须重新按住确认 |
| ⑤ 冷却 | 写入成功后 5 秒内不允许再次保存（防连点重复 write），按钮会显示上次保存时间 |
| ⑥ 结果 | 只看设备回显：有 `[OK]` 才算确认成功；没有成功标志就提示去【CLI】看原文，绝不假报成功 |

**不会做的事**：不会自动保存、不会在改完配置后"顺手 write"、不会自动重试、不会替你回答设备的 y/n 提问
（设备如果停下来问 y/n，弹窗会提示你到【CLI】页手动处理）。

**真机实测（2026-09-19，锐捷交换机；型号与版本已省略）**

```
命令写的是：write
设备回显是：write
            Building configuration...
            Write to boot config file: [/config.text]
            [OK]
```

- 界面按 `[OK]` 判定为**已保存**，并把这四行原始回显完整留在弹窗里（可直接复制）
- 软件自己发的命令与设备回显分别记在上面的两段，**格式与判定规则一致**
- 落盘独立复核（用另一个裸 Telnet 客户端，不经过本软件）：写入后 `running-config` 与
  `startup-config` 完全一致；`startup-config` 唯一的变化是本次未保存的那一行被写了进去
- 同一台真机上另外验证过：未按住**不会发送任何字节**（设备侧配置无变化）

> 设备原生帮助也确认 `write` 是标准写法：`write ?` → `memory / network / terminal / <cr>`，
> 其中 `<cr>` 就是"直接保存到 NV 内存"。

## 4. 安全与行为约定

这些不是"建议"，是软件的行为边界：

- **改配置必须走预览**：GUI 操作 → 生成命令 → Command Preview 弹窗 → 你点[执行] → 才发送
- **绝不自动 `write`**：软件不会自己保存、不会在改完配置后"顺手 write"、不会自动重试
  （唯一入口是顶栏 [保存配置]，且必须**按住按钮 1.2 秒**；成功后还有 5 秒冷却，防连点）
- **断线禁止发命令**；设备未连接时按钮是灰的
- **不自动轮询**：所有数据都是你点[刷新]那一刻的快照
- **原始输出必须保留**：解析失败不影响你看到设备原文
- **Excel 只读导入**：绝不修改你的原始表格；资源库完全离线（本地 JSON）
- **密码类信息不落盘**：Telnet 密码、SNMP Community、Enable 密码都不写入设置文件、不写日志、不弹框显示
- **权限也是显式状态**：CLI 与所有图形化页面共用同一份权限判定，普通模式下的配置命令会被直接拦下来并给出提权入口

## 6. 连不上交换机怎么办

### 第一步：点 [连通性自检]

【连接】页的 **[连通性自检]** 只做只读探测，不改任何设置，一次给出五项结论：

```
✓ 串口 · COM3 存在（共检测到 1 个串口）。
✓ Telnet 地址 · 192.0.2.49
! 本机网段 · 本机网卡：192.0.2.23/24；与目标 192.0.2.49 同网段。
! Ping · 192.0.2.49 ping 不通（TimedOut）。很多交换机会禁用 ping，不代表 Telnet 一定不通。
✗ Telnet 端口 23 · 192.0.2.49:23 通了，但对方拒绝连接（23 端口没有服务）。
```

**"本机网段"那一行只是参考**：它说明的是"走不走网关"（同网段=二层直达；不同网段=要经过路由）。
**跨网段本身不会导致连不上** —— Telnet 就是 TCP 连到 `目标IP:23`，校园网/办公网里跨网段 Telnet 到交换机是常态，
只要有路由、中间放行 TCP、交换机开着 Telnet 就能连。真正"能不能连"看的是**「Telnet 端口」那一行**（它真的去连了一次 TCP）。
跨网段连不上时按顺序查：① ping 网关/目标 ② 中间防火墙或 ACL 是否放行 TCP 23 ③ 交换机是否开启 Telnet 服务。
（"配同网段静态 IP"只适用于**网线直连交换机管理口**这种场景。）

### 第二步：看报错编号

连接失败时，页面会显示 `[编号] 标题 / 原因 / 怎么修 / 环境 / 原始错误`，右上角 **[复制报错]** 可整段复制发给同事或开发者：

| 编号 | 含义 | 常见原因 | 怎么修 |
| --- | --- | --- | --- |
| `NET-01` | 没有填写交换机地址 | 没填 IP | 填管理 IP，或地址簿选中后[填入 Telnet 参数] |
| `NET-02` | 地址无法解析 | IP 写错 | 检查 IP（例：`192.0.2.49` 写成 `192.0.2.499`） |
| `NET-03` | 本机网络不可达 | 没有到目标的**路由**（没有默认网关 / 网卡没配 IP / 被禁用） | 跨网段：先 ping 网关、确认能上到目标网段；同网段直连：给网卡配同网段静态 IP |
| `NET-04` | 目标主机不可达 | 路由到不了目标网段 / 同网段链路不通或接错口 | 跨网段：按路由顺序查网关与中间设备；直连：检查网线，确认接的是管理口 |
| `NET-05` | 对方拒绝连接 | 交换机没开 Telnet | 交换机上 `enable service telnet`，vty 允许 telnet |
| `NET-06` | 连接超时 | 被中间防火墙/ACL 拦、路由不通、网线不通、交换机没回 | 跑[连通性自检]看「Telnet 端口」；跨网段先查路由与放行，直连再查网线；（不同网段本身不是原因） |
| `NET-07` | 被本机拦截 | 防火墙 / 安全软件 | 允许「235修网助手」通过防火墙 |
| `NET-08` | 其他网络错误 | — | 跑[连通性自检]看四项结论 |
| `COM-02` | 串口不存在 | 驱动没装 / 选错口 | 装 USB-Serial 驱动 → 设备管理器确认 COM 口 → [刷新串口]选择 |
| `COM-03` | 串口被占用 | 其它程序占着 | 关掉 SecureCRT / PuTTY / 串口助手，拔插一次线 |
| `COM-04` | 串口名不合法 | 手工填错 | 用下拉框选择 |
| `COM-05` | 串口打开失败 | 线缆 / 驱动异常 | 换 USB 口或换一根线 |
| `CLI-01` | 没看到登录提示符 | 设备不出提示符 | 在终端里按一下回车；出现账号密码提示就手动输入 |
| `CLI-02` | 登录后没有看到提示符 | 账号密码不对 | 在 CLI 里手动重新输入账号密码 |
| `CLI-03` | 串口已连接但设备没输出 | 线插在网口 / 没上电 / 波特率不对 | 三条都查一遍（多数设备 9600） |
| `CLI-04` | 已连接，但 CLI 初始化出错 | 读写出错 | 直接进 CLI 手动输入；或断开重连 |

### 常见现场情况速查

| 现象 | 处理 |
| --- | --- |
| `[刷新串口]` 里一个 COM 口都没有 | 装 USB-Serial 驱动（CH340 / PL2303 / FTDI），插好线再刷新 |
| 只有 COM1 可选 | 笔记本主板自带的虚拟口，**不是**你的配置线；拔插一次线看哪个口出现 |
| 串口连上了但终端一个字都没有 | 线插在交换机**网口**上了 / 交换机没上电 / 波特率不对（`CLI-03`） |
| Telnet 提示"对方拒绝连接" | 网络是通的，交换机没开 Telnet 服务 |
| Telnet 没反应或超时 | 电脑和交换机不在同一网段（看自检结论） |
| 连上了但显示"未获取设备名" | 设备提示符里没有主机名；在任意设备页点一次[刷新]即可解析 |
| 要看设备到底回了什么 | 任何页面展开下方 **原始输出** → [复制原始输出] |

Console 参数默认 `9600 / 8 / None / One / None`，大多数锐捷设备出厂即如此。

## 7. 常见问题

**Q：为什么点了[刷新]没数据？**
A：先确认已连接（不是"连接失败"）。数据都是点刷新那一刻从设备读的；设备不支持某条命令时，页面会提示"未解析出结构化数据"，这时展开原始输出能看到设备实际回了什么。

**Q：表格里的数据和设备实际不一致？**
A：MAC 表会老化、资源库是**规划数据**不是实时状态。以"设备实时数据"（各页 [刷新]）为准；资源库用来对照"应该在哪"。

**Q：会不会误改交换机？**
A：不会自动改。所有配置都要经过 Command Preview 弹窗确认；保存（`write`）也要你亲手按住按钮 1.2 秒才会发送，
软件不会自动保存、不会替你回答设备的 y/n 提问。详见 3.13。

**Q：换电脑怎么带走数据？**
A：把 `%LocalAppData%\235NetworkAssistant\` 里的 `resources.json`（资源库）和 `settings.json`（设置）拷过去即可。

**Q：设备输出很长（比如 `show running-config`）会卡住吗？**
A：不会。软件会自动处理 `--More--` 分页（发空格续页，最多 1000 页保护），并用"空闲超时"判断结束——只要设备还在吐数据就不会被判超时。

**Q：终端里看不到自己打的字？**
A：终端模式靠**设备回显**显示输入。某些设备不回显，勾上 CLI 工具条的 **本地回显** 即可。

**Q：按 Tab 之后冒出一大堆东西，是软件的问题吗？**
A：不是。Tab 只做命令补全，软件**只往设备发一个 Tab 字节（0x09）**，屏幕上那一坨是**交换机自己回的**：
真实设备会把补全后的整行重打一遍；候选有多个（或设备实现得比较"热情"）时就会列出整张命令表。
想确认可以在 CLI 页 [保存输出] 导出原始输出，那一坨必然在里面（设备发的原文）。
用 `work/cli_tab_test.js` 可以实测：软件发出的字节恒为 `conf t<09>`（只有一个 Tab）。

**Q：终端里的光标位置会不会乱跑？**
A：不会。终端是只读控件，光标只表示"下一个字符会出现在这里"，软件每次写入后都会把它钉在**末尾**；
退格引起的擦除是**增量删除**（不整体重绘），所以光标、滚动位置和你的选区都不会被打断。
如果你选中了一段文字准备复制，软件也不会去动光标/选区。

> 这一节是**如实交代**，不是免责声明：下面每一条都确认过现象，也都写清了绕过办法。

### 8.1 会遇到的（有绕过办法）

| 现象 | 说明 | 怎么办 |
| --- | --- | --- |
| ~~连上设备后，第一条命令偶尔读回空表~~ | **已修（2026-09-24）**：根因是"上一条提示符迟到"落进本轮缓冲 → 命令被误判已结束；现在必须**先看到回显或内容行**才允许靠提示符结束 | 真机连跑 6 次全部正常；若仍出现请把 `work\session-*.log` 发我 |
| **核心交换机 MAC/ARP 大表要拉很久，还会被设备限速** | 上万行 + 设备对连续 GETBULK 可能限速 | 用【SNMP】页的 **[继续拉取大表]** 分几轮拉；端口列会逐轮补齐 |

| **Telnet 空闲一会儿就断** | 交换机的 VTY 空闲超时，或中间有隧道/NAT 回收会话 | 连接页 Telnet 面板把 **保活(秒)** 填 30 |
| **某些 USB 串口线接上后设备无输出** | 个别适配器拉 DTR 会让设备复位/不出数据 | 连接页 Console 面板取消勾选 **拉 DTR** |

### 8.2 还没验证到的（下一版补）

- **Telnet NAWS（把窗口尺寸告诉设备）**：**已验证设备会接受协商，收益未证实**。具体型号已省略。
  （日志有 `设备接受了 NAWS`），但同一条 `show running-config` 的翻页次数：Console（无 NAWS）**2 页**、
  Telnet（NAWS 200×60）**3 页** —— 方向与预期相反，说明设备的分页没有按我们报的行数走。
  机制本身符合 RFC、对不支持者无害，代码保留；**不再深挖**（那是锐捷私有分页实现），
  除非现场出现"大配置翻页翻不完/翻错"的实测案例。
- **粘贴多行确认 / 退格发 DEL / 保活 / DTR-RTS** 四项：功能已实现且有自检覆盖，还差人工手感确认。

### 8.2.1 SSH.NET 依赖

项目已升级至 `SSH.NET 2026.0.0`。旧版 `2025.1.0` 有安全公告，修复版本为 `2026.0.0`：

| 公告 | 影响面 | 我们的情况 |

| [GHSA-q939-rpr3-3284](https://github.com/advisories/GHSA-q939-rpr3-3284)（High 7.1） | `ScpClient.Download(..., recursive)` 递归下载时，服务端返回的文件名含 `../` 可写到目标目录之外 | **未使用** SCP 相关 API |

### 8.2.2 写配置的兜底到什么程度（使用前请知情）

**这个工具没有自动兜底**，请按下面的方式自己留后路：

- ❌ **不自动抓快照、不自动回滚、不生成撤销命令**：改坏了要自己收拾 —— 用【备份】页先备份、
  用"配置对比"核对差异，再手工回退。
  （曾经做过"下发前自动抓改前快照"，按用户判断**已从产品里移除**：我们从不自动 `write`，
  `startup-config` 一直是上一份好的，改坏了**重启即回滚**，那条快照没有实际价值，反而在慢串口/隧道上添负担。
  实现与恢复步骤留档在 `work/未打包功能/改前快照/`。）
- ❌ 没有"上行口 / 管理口保护名单"：工具**不会**阻止你把上联口 shutdown。动手前先看清端口。
- ❌ **不支持单实例互斥**：同一台电脑能同时开多个本程序、多个窗口连同一台设备。
  实测过两个窗口抢同一个 COM 口会报"串口被占用"；**两个 Telnet 窗口同时改同一台设备是危险的 —— 现场只开一个窗口**。

**建议的现场姿势**：改配置前先点【备份】页备份（或记住"重启即回滚"这条底线）；
改完用"配置对比"核对；重要改动在操作台账（`operations-yyyyMMdd.csv`）里能查到**实际下发的命令**。

### 8.2.3 SSH 主机密钥验证

首次连接未知 SSH 设备时，程序会先获取并拒绝未验证的握手，再显示 IP、端口、密钥算法和 SHA256 指纹；用户确认已通过 Console 或其他可信渠道核验后，才保存公钥并继续登录。取消不会保存记录，也不会发送登录凭据。

后续连接只接受与本地记录完全匹配的公钥。公钥变化会中止连接，并显示旧、新指纹；请通过可信渠道核验后，在【连接 → SSH → 管理已信任设备】更新或删除记录。信任库独立保存在 `%LocalAppData%\235NetworkAssistant\ssh-trusted-hosts.json`，只包含公开主机密钥，不保存账号、密码或私钥。信任库损坏时连接会被拒绝，程序不会自动用空列表覆盖。

### 8.3 明确不做的

- 不做自动故障诊断、拓扑推理、批量下发（V0.1 范围外，见项目计划）。
- 不改设备的账号、密码、SNMP 配置、SVI：本工具只做只读采集 + 你确认过的配置命令。
- 不保存任何凭据（Telnet 密码 / Enable 密码 / SNMP Community 都不落盘）。

#### V0.2.1 修订（2026-09-20：配置模式修复 + 真机 walk 回放回归）

- **修掉"配置命令没进配置模式"（致命）**：端口页 `no shutdown`、VLAN 页新建 VLAN 点了没效果。
